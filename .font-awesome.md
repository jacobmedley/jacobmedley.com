# Font Awesome Configuration

Configured with setup-fa on October 3, 2026. Keep this file with the project so
add-icon and suggest-icon can reuse the verified integration.

## Integration

- **Method:** Existing hosted Kit JavaScript embed delivering Web Fonts + CSS.
- **Framework:** Next.js App Router / React / TypeScript; npm.
- **Version:** 7.3.1, observed from the Kit on October 3, 2026. Hosted configuration can change independently of this repository.
- **License:** Pro, reported by the Kit configuration.
- **Kit ID:** 644e13edf7
- **Kit Revision:** Not verified; do not infer it from asset URL segments.
- **CDN URL:** https://kit.fontawesome.com/644e13edf7.js
- **Entry point:** app/layout.tsx, existing next/script with afterInteractive and crossOrigin="anonymous".
- **Families:** Classic Thin verified in the browser. Custom fa-kit identity symbols are referenced by source. Complete Kit family/subset coverage has not been authenticated through the CLI.

## Defaults

- **Style:** thin
- **Family:** classic

## Import Pattern

Use the existing class-based markup; no npm icon import is required:

```tsx
<i className="fa-thin fa-hearts" aria-hidden="true" />
```

Keep the single hosted embed in the root layout. Do not add a second loader,
switch to a Kit npm package, or introduce React SVG components as part of a
routine icon addition.

## Conventions

- Preserve role-specific icon dimensions, color inheritance and accessible names.
- Decorative icons use aria-hidden; meaningful icon-only controls and metadata receive an accessible name on their owning element.
- Keep custom fa-kit fa-jm-icon-full and fa-kit fa-jm-icon-cropped identity assets.
- components/ui/CaseStudyModal.tsx deliberately maps four historical Brand names to Thin alternatives. Do not change these without verifying the rebuilt Kit's coverage.
- Preserve existing legacy aliases until a separate normalization pass verifies their use.
- The private portfolio design packet and its category mappings live outside this public repository. This setup does not import private copy or approve new case categories.

## Verification and Limits

The installed setup-fa fallback fetched Kit metadata successfully. Its family
listing describes release/license availability; it is not proof of the Kit subset.
The fa CLI is absent, so authenticated complete subset coverage was not checked.

The normal hosted embed was browser-tested on a local isolated verification page.
check, hearts, brain, hexagon-nodes, paintbrush-pencil, microchip-ai and
person-meditating each rendered with one actual FontAwesome7Pro-Thin glyph.
briefcase, layer-group, cube and people-group also rendered visibly. The test
included no fallback Font Awesome stylesheet. Earlier direct stylesheet HTTP 403
responses do not represent the normal embed result.

No npm dependency, layout loader or application component changed for this setup.
